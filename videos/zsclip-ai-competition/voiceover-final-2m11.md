## 口播正文

### 0:00 - 0:14 女声：系统工具不是功能堆叠

[轻一点，像把观众带进真实办公场景]
如果一个工具每天都挂在系统里，它就不能只做功能堆叠。它要够轻、够稳，还要真的理解你每天复制过的那些碎片：合同、截图、发票、命令行、文件路径。

### 0:14 - 0:34 男声：从 Python 小工具一路迭代

[像在讲自己的真实来路，不要播音腔]
ZSClip 不是我一上来就用 Rust 写出来的。最早它只是一个 Python 小工具，因为我每天处理资料时，复制过的东西太多，想找回来太麻烦。我先做了一个自己能用的版本，然后一直迭代到现在。

### 0:34 - 0:50 女声：为什么迁到 Rust

[追问式，不要像广告词]
那为什么后来一定要迁到 Rust？剪贴板看起来只是一个小工具，但它是常驻系统里的工具。你越依赖它，越会在意它是不是卡、是不是重、是不是和系统隔了一层。

### 0:50 - 1:10 男声：纯原生 UI 的取舍

[语气认真，像解释自己的技术选择]
所以主力版本我迁到了 Rust，并且开始做纯原生 UI。我的目标不是套一个网页壳，而是让窗口、托盘、热键、剪贴板、弹窗这些能力都尽量贴着系统运行。常驻工具的第一层体验，其实就是安静。

### 1:10 - 1:30 女声：VV 与复制记录

[看着画面讲，像在展示每天会用的小动作]
先看最常用的 VV 模式。复制过的文本、图片、文件会进入记录，也可以变成常用短语。输入 `vv`，候选窗贴着光标出来，按数字就能粘贴。这个动作很小，但每天用几十次，就会变成真正的效率。

### 1:30 - 1:52 男声：搜索的独特点

[语气具体一点，像在说真实办公场景]
搜索是我觉得 ZSClip 和普通剪贴板软件不一样的地方。它不是只搜文字。比如我想找今天 WPS 里的合同、刚才那张截图、某个文件记录，可以按应用、日期、时间、类型一起筛。后面我还会加附近记录，直接看命中内容前后的复制时间线。

### 1:52 - 2:08 女声：右键分组与文件类型

[像在提示观众看右键菜单]
分组也不是单独开一个复杂入口。复制记录、常用记录里都可以右键处理：继续搜索、加入短语、加入分组。后续分组还会加文件类型选项，让文本、图片、文件这些素材更容易被整理。

### 2:08 - 2:26 男声：OCR 与素材化

[语气带一点“这个真的有用”的兴奋]
OCR 是另一个特别适合办公的能力。很多资料不是以文档形式出现，而是先变成截图。ZSClip 可以把图片里的字取出来，再清洗、翻译、存成短语。它不是只保存历史，而是把复制过的东西重新变成可复用素材。

### 2:26 - 2:44 女声：0.1M 内存占用美学

[这里收着讲，让任务管理器自己给证据]
再看任务管理器。对常驻系统工具来说，内存占用不是一个冷冰冰的数字，它是产品气质的一部分。ZSClip 想追求的是 0.1M 级的内存占用美学：能不占就不占，能晚加载就晚加载。

### 2:44 - 3:01 男声：优化不是为了跑分

[语气认真，像在讲自己的工程审美]
为了这个方向，我做了分页加载、虚拟列表，只画可见区域，正文和图片按需补全，窗口隐藏后释放缓存。它不是为了跑分，而是因为剪贴板这种工具应该像系统的一部分，存在感越低，越说明它做对了。

### 3:01 - 3:18 女声：ZSUI 是开放工程

[放慢一点，像在定义长期工程]
ZSUI 是这个项目后面更大的部分。但我不想把它讲成一个人维护三平台 UI 框架。它更像一个开放工程：把托盘、热键、弹窗、设置页、列表这些系统工具能力写成明确合同，让 AI 和贡献者可以按合同补组件、补平台、补测试。

### 3:18 - 3:30 男声：收尾

[真诚一点，像发布一个仍在继续迭代的软件]
所以 ZSUI 不是另一个通用 UI 框架，而是 Rust 原生系统工具应用框架。它应该类型安全、显式、组合式、低魔法、可降级，少运行时反射，少全局状态。Windows 是主力版，其它平台还在初代测试，欢迎下载试用、加群反馈，我会第一时间修。
