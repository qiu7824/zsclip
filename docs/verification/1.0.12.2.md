## 证据与实现

### VV

`vv_popup_wnd_proc` 原先在跨行后整体 invalidate，WM_PAINT 直接清背景并逐项绘制到窗口 DC。现将整个帧画到专用 `PaintBuffer` 后一次复制，同时响应 WM_ERASEBKGND；缓冲按需复用，隐藏时释放。没有改 `vv_hook` 或 `vv_session` 的触发语义。

### 权限

[issue #45](https://github.com/qiu7824/zsclip/issues/45) 的公开截图已逐像素查看。图中明确写着内容已写入剪贴板，失败阶段是自动粘贴；不能据此声称剪贴板读取被权限阻止。

[Microsoft SendInput](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-sendinput) 说明输入注入受 UIPI 限制，只能写入同级或更低完整性进程。仅凭 GetLastError/返回值无法识别 UIPI 原因。[完整性级别文档](https://learn.microsoft.com/en-us/windows/win32/secauthz/mandatory-integrity-control) 描述了 low/medium/high/system 的级别关系。因此代码先查 TokenIntegrityLevel 和 TokenUIAccess，再区分输入受阻与剪贴板失败。

本次 UAC 重启只由用户在权限提示中明确选择触发，默认按钮为“否”。使用 Windows `runas`；失败/取消不退出旧程序；成功启动后等待旧进程退出，保留解析后的数据目录和原单实例标识。该交互没有在本轮实际触发，需人工验收 UAC 同意/拒绝及不同账户情况。

### Excel 与类似富文本

[Ditto Clip.cpp](https://github.com/sabrogden/Ditto/blob/master/src/Clip.cpp) 将格式存入 `m_Formats`，描述优先从 CF_UNICODETEXT 获取，两者分离。[CopyQ itemtext.cpp](https://github.com/hluk/CopyQ/blob/master/plugins/itemtext/itemtext.cpp) 的 `formatsToSave()` 在开启富文本时保存 text、UTF-8 text 和 HTML；其渲染使用 HTML，失败或空结果回退文本。[CopyQ Windows clipboard backend](https://github.com/hluk/CopyQ/blob/master/src/platform/win/winplatformclipboard.cpp) 同时检查序列号和排除监控的格式。

ZSClip 采用的原则是“正文用于显示，格式用于恢复”，并非见到 HTML 就显示格式名字，也不把 HTML 标签写进正文。Unicode 显示值用于日期、货币、公式结果等摘要；HTML 保留项目既有安全筛选后的选区和样式。带格式记录不再经过会删去首尾单元格分隔符和 Unicode 连接符的纯文本清洗。

本次没有新增 RTF/BIFF/OLE 任意二进制格式存档。不能宣称 Excel 私有格式、公式、嵌入对象或所有 Office 样式无损往返；RTF-only 来源仍使用其 Unicode 文本，已有 HTML 来源保留支持的 HTML 样式。修改仅改善已支持格式组合，避免用未审计的工作簿私有数据替代选区。
