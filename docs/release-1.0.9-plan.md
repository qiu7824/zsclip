# ZSClip 1.0.9 开发计划

1.0.9 聚焦 Windows 日常使用的可靠性、搜索响应和内容可读性。发布首要条件是 QQ 中取消 VV 后草稿完整保留，以及搜索输入和结果加载达到性能目标；同时修复粘贴音效和图片另存，完善字号、短语标题、VV 全文预览和本机富文本粘贴。

开发基线为 1.0.8。以下为计划范围与验收目标，工期和性能指标均为估算或目标值。

## QQ 中 VV 取消与输入保护

复现场景：QQ 编辑区已有正文，输入 `vv` 打开候选窗口，按 Esc 取消，再继续输入中文或英文。缺陷表现包括取消后正文暂时仍可见、下一次输入时整段正文被替换或消失。

### 实现任务

1. 将键盘钩子、显示定时器、候选选择与取消统一为带会话编号的状态流：空闲、等待显示、已显示、已取消、已选择。取消或焦点改变后，旧的显示、重试、选择消息全部失效。
2. 统一 VV 钩子与快速窗口钩子的 Esc 处理归属。VV 等待显示或已显示时，由 VV 消费该次 Esc 的按下、长按重复和松开事件；松开后重新按 Esc 时，恢复目标应用正常行为。
3. QQ 的 VV 显示与取消流程不注入通用 Esc。输入法组合处理必须限定到已确认的组合会话；无法确认时采用保守关闭策略，不尝试清空编辑区或恢复整段文本。
4. 取消不选择全部正文、不删除既有正文、不改变系统剪贴板。普通字母继续输入时关闭候选并传递一次；退格关闭候选后只产生一次自然退格。
5. 只有无修饰键的有效数字候选选择才执行粘贴；Ctrl、Alt、Win、Shift 组合不得触发误选。选择后仅处理可确认属于触发串的字符，保留触发前正文。
6. 以窗口、焦点控件和会话编号校验最终粘贴目标，防止同窗口切换编辑区或 Alt-Tab 后粘贴到新位置。

排查入口：`src/platform/hook.rs`、`src/app/vv_hook.rs`、`src/app/vv_popup.rs`、`src/app/main_low_level_input.rs`、`src/app/main_events.rs`、`src/platform/input.rs`。

当前代码存在显示时注入 Esc、物理键盘事件只解析按下、两个钩子分别处理取消、延迟显示缺少完整会话状态等路径。这些路径分别进行事件时序验证，不能用单一代码推测代替 QQ 实机复现。

### 验收

- QQ 普通消息与多行草稿分别执行 `正文 → vv → Esc → 继续输入 → 提交输入法候选`，正文完整保留，输入追加在预期光标位置。
- 覆盖快速按 Esc、长按 Esc、第二个 v 后立即取消、候选显示前取消、取消后切换中英文和双拼状态。
- 覆盖数字选择、Ctrl/Shift 加数字、退格、同窗口切换输入控件、Alt-Tab，确认无误粘贴、重复按键或旧窗口重新弹出。
- 记事本、浏览器输入框、微信及 WPS 执行同类回归；QQ 为独立发布阻断用例。
- 跟踪记录仅包含按键类别、时间戳、会话状态和焦点标识，不记录消息正文。

## 编辑区选区粘贴

文件重命名等原生编辑区中的粘贴遵循选区语义：仅替换选中部分，保留前后未选内容；没有选区时在光标处插入，全选时才替换全部。通过原生选区替换消息保留撤销，不通过重写整框或补回后缀模拟粘贴。

开发入口：`src/app/main_paste.rs`、`src/platform/paste_target.rs`。验收覆盖部分选区、光标插入、全选、中文及 emoji、原生撤销、桌面和资源管理器重命名。

## 搜索响应与查询调度

现有搜索已具备 280 ms 去抖、后台分页和过期结果丢弃。性能工作应覆盖查询排队、执行中取消、逐行过滤及主线程结果应用，不能只通过缩短去抖时间完成。

### 实现任务

1. 分别记录输入回显、去抖等待、任务排队、SQL 执行、保护过滤、结果应用和首屏绘制耗时。使用合成记录建立 200、1,000、10,000、100,000 条数据集，包含长正文、文件路径和富文本。
2. 用户输入变化时立即更新查询代次；队列合并仅保留最新请求。让正在执行的过期搜索可中断，不能只在 SQL 执行前后判断是否过期；取消仅作用于对应搜索连接和会话，不影响后台写入。
3. 首屏搜索优先于旧条件下的后续分页，限制任务数量；取消被视为正常状态，不显示数据库错误。主窗口与快速窗口分别管理查询代次。
4. 对 SQL 使用执行计划与分段计时定位成本。优先优化筛选条件、日期范围和排序索引，避免对每行重复执行无必要的日期格式化。
5. 将敏感内容过滤的重复文件元信息读取和共享锁开销纳入专项优化。采用有版本的匹配快照或等效缓存，并在查询返回、预览和粘贴前检查保护状态变化；保护数据不可读时保持阻止泄露的行为。
6. 保留中文子串、单字、英文、文件名、日期、应用与组合搜索的既有语义。仅在测量证明需要时引入全文索引；中文单字/双字、标点、大小写和索引重建必须有等价性用例，不能直接以默认分词替换子串搜索。
7. 主线程只应用当前查询的轻量首屏结果；正文、图片解码和预览内容按需异步加载，不能在悬停时同步等待数据库。保留原列表直到新结果可用，明确标为旧结果并暂时禁止选择；超过 150 ms 显示轻量查询状态，避免闪空列表和误粘贴旧结果。
8. 在队列和 SQL 优化后，将普通输入去抖目标调整为约 120–180 ms，并通过输入法组合态测试确定最终值；Enter 可立即提交，组合输入期间避免无效的反复检索。

排查入口：`src/app/main_search.rs`、`src/app/data.rs`、`src/db_runtime.rs`、`src/secret_vault.rs`、`src/app/state.rs`。

### 性能验收目标

基准环境采用 Windows 10/11、4 核 CPU、16 GB 内存和本地 SSD，记录具体硬件、数据库大小、单条正文长度和冷暖缓存状态。各场景至少采集 50 次查询，以最后一次输入到首屏结果绘制完成为总耗时，包含去抖时间。

| 指标 | 目标 |
| --- | --- |
| 输入框按键回显 | P95 不超过 50 ms，连续输入不丢字、不冻结 |
| 200–1,000 条暖缓存首屏结果 | P95 不超过 300 ms |
| 10,000 条暖缓存首屏结果 | P95 不超过 500 ms |
| 100,000 条暖缓存首屏结果 | P95 不超过 1,000 ms |
| 100,000 条冷启动首次查询 | 不超过 2 s，期间界面可操作 |
| 过期搜索收到取消后的退出延迟 | P95 不超过 100 ms |
| 查询正确性 | 最后输入对应最后结果，旧结果不得覆盖；搜索结果、分组和日期条件正确 |

覆盖无结果、稀有词、常见词、中文单字/双字、超长文本、组合条件、前后相邻记录查询、快速连续输入与清空、正在采集剪贴板、正在同步和保护分组状态变化。对“记录存在但搜不到”单列正确性测试，覆盖旧库升级、查询失败后再次检索、切换分组和关闭重开搜索；不得将异常当作正常空结果。性能未达标时保留分段数据继续定位，不通过减少正确结果或跳过保护过滤达标。

## 粘贴音效一致性

复制音效与粘贴音效使用独立开关。粘贴音效覆盖主列表、快速窗口、快捷粘贴和 VV 发起的粘贴操作；普通系统 Ctrl+V 不属于该完成通知范围。先按入口、内容类型和是否经过延迟重试分解复现，区分“仅复制到系统剪贴板”与“应用执行粘贴”。

统一粘贴操作完成后的播音调度，成功路径至多一次；取消、注入失败、仅复制内容时不播放粘贴成功声。保留防重复机制，补充播放器返回值诊断及失效自定义音效文件的回退处理。

开发入口：`src/app/settings_toggle_state_general.rs`、`src/app/main_paste.rs`、`src/app/main_events.rs`、`src/shell.rs`。

验收覆盖两个开关的四种组合、默认与自定义音色、保存重启、文字与异步图片、各粘贴入口和重试；复制与粘贴开关互不影响，成功一次一声，失败或取消不误响。

## 图片另存为 PNG

“另存为 PNG”接入原生保存对话框，默认提供有效的 `.png` 文件名。确认目标路径后生成 PNG 文件；取消不创建文件、不打开目录。内部图片定位与缓存落盘工具继续用于取图，不将其返回原路径的行为当作另存完成。

开发入口：`src/app/main_row_commands.rs`、`src/app/data.rs`、`src/platform/file_dialog.rs`。保存文件与打开所在目录保持不同操作；本项不需要调整菜单命令编号。

验收覆盖已落盘图片、内存图片、中文和空格路径、透明图片及重复文件名。目标存在时进行覆盖确认；拒绝覆盖、无权限、源图损坏或丢失均有明确结果，原文件不受损。输出必须能按 PNG 解码且尺寸、像素与透明通道正确；“打开所在文件夹”、导出为文件及拖出图片分别回归。

## 字号调节与高 DPI

设置增加“内容字号”，提供默认、12、14、16、18、20 逻辑像素档位。旧配置映射到“默认”并维持原有外观；数值档覆盖主列表、快速窗口、VV 候选、文本预览和搜索输入。标题及图标遵循现有界面层级。

将内容字号与行高解耦；字号增大时按字体度量计算最小行高、内边距和点击区域。字号变化立即生效并持久化，刷新字体和布局缓存，不重载全部记录。

开发入口：`src/app/state.rs`、`src/settings_model.rs`、`src/app/settings_general_page_startup.rs`、`src/app_core/main_window.rs`、`src/app/main_search.rs`、`src/app/vv_popup.rs`、`src/platform/dpi.rs`。同时接通实际 Windows 控件、设置收集和应用逻辑。

验收覆盖 4K 显示器、Windows 100%/125%/150%/200% 缩放、混合 DPI 双屏、深浅主题及重启。字体清晰，内容不裁切、不重叠，点击位置正确；已转换为物理像素的渲染命令不得再次缩放。

## 常用短语独立标题

常用短语增加独立标题字段，提供“标题＋正文”编辑和单独重命名，并在设置中提供“启用短语独立标题”开关。关闭时显示正文摘要并隐藏标题编辑、重命名入口；保留已有标题数据，重新开启后恢复。标题可空，长度上限为 60 个 Unicode 字符，允许同名；空标题回退到正文摘要。标题不复用 `preview` 字段，正文编辑不得覆盖标题。

开发入口：`src/app_core/main_window.rs`、`src/db_runtime.rs`、`src/app/data.rs`、`src/app/main_row_commands.rs`、`src/app/main_renderer.rs`、`src/app/vv_popup.rs`、`src/app/main_row_tools.rs`。

数据库增加兼容旧记录的标题字段，贯通新建、编辑、重命名、摘要/完整查询、分组复制和完整数据库备份恢复。主列表和 VV 优先显示标题，全文预览展示正文；搜索同时匹配标题和正文。单项导出文件名优先采用清理过文件名非法字符的标题，导出内容与复制粘贴均仅包含正文。

同名不同正文、同正文不同标题的显式保存短语均可并存。仅重命名时不清除正文富文本；标题遵循条目和分组的访问保护。局域网维持现有内容同步语义，不把标题拼入正文，也不把普通文本同步扩展为短语库同步。

验收覆盖新建、改名、取消、空标题、超长标题、中文和 emoji；标题及正文分别搜索成功，VV 与主列表名称一致且实际粘贴不含标题；正文编辑、重启和备份恢复后标题不丢，旧版无标题短语继续可用。

## VV 长文本预览

为 VV 候选增加非激活全文预览：鼠标悬停约 200 ms 显示，键盘上下键选择候选时可查看对应内容。预览保留换行并可滚动，不抢走目标编辑区焦点；1–9 继续承担直接粘贴功能。

当前候选摘要与完整正文分开处理。只对当前预览项异步读取完整正文，结果绑定记录编号、VV 会话编号和数据代次，防止快速切换时串项。关闭 VV、删除记录或保护状态变化时关闭预览并清除相关缓存。

开发入口：`src/app/vv_popup.rs`、`src/app/vv_hook.rs`、`src/app/data.rs`、`src/app_core/main_window.rs`。先完成 VV-01 的会话和按键归属，再接入预览导航。

验收覆盖万字文本、前 120 字相同的多条记录、连续换行、快速切换候选、屏幕边缘和 200% DPI。能够查看区别所在的全文位置；预览操作和取消后继续输入均不修改原编辑区。受保护内容不得通过摘要、正文或旧缓存显示。

## 本机富文本与表格样式

正式支持范围为历史记录中可通过 HTML 表达的字体颜色、加粗、字号、基本单元格填充、边框及表格行列结构。公式、图表、宏、嵌入对象、Excel 私有格式和跨设备富文本传输另行评估，不列入 1.0.9 的格式保留承诺。

### 实现任务

1. 分离保存用的完整 HTML 剪贴板载荷与预览用的片段，保留必要的外围样式上下文；旧的片段记录继续可读，不能补造其已丢失的样式。
2. 完成采集、数据库迁移、正文加载和剪贴板写回全链路。普通粘贴同时提供 Unicode 文本和有效 HTML；纯文本粘贴只提供文本。HTML 偏移按 UTF-8 字节计算。
3. 复用“保留富文本”设置，说明保存与粘贴范围；新安装默认开启，升级用户保留已有选择。普通粘贴优先恢复条目已保存的格式，专用纯文本命令明确去除格式。
4. 编辑或 AI 清理导致文字变化后，清除过期格式，保证可见文字与实际粘贴内容一致。多条合并粘贴按纯文本执行。
5. 修正去重回退：相同文字但颜色或粗细不同的条目不得误合并；新格式签名与旧条目兼容。
6. 新载荷纳入已有容量预算、清理、备份、迁移及保护过滤。格式损坏或超限时保留可用文本并给出明确状态；不能在预览中执行脚本或加载远程资源。
7. HTML 是否足以覆盖指定样本在开发早期验证；如确需 RTF，先补齐大小限制、存储、恢复与保护链路，再纳入发布范围，避免无边界保存所有自定义格式。

开发入口：`src/platform/clipboard.rs`、`src/app/main_clipboard_capture.rs`、`src/app/main_paste.rs`、`src/app/data.rs`、`src/db_runtime.rs`。

### 验收

- WPS 文字、WPS 表格及浏览器富文本构成执行矩阵；覆盖中文、英文、颜色、加粗、字号、边框、填充、多行多列表格和包含 head 样式的 HTML。
- 关闭源应用、重启 ZSClip 后，从历史记录恢复仍保留声明支持的基本样式；粘贴到纯文本编辑器能够正确回退。
- 通过真实 Excel 格式样本执行载荷解析与恢复测试，并单列 Excel 客户端往返测试状态；WPS 测试通过不能替代 Excel 实机兼容结论。
- 旧库升级、同文不同样式、编辑后粘贴、纯文本命令、超限与损坏数据、图片和文件记录全部回归。
- 发布说明按实际验证的软件与格式列出兼容范围，不使用“Office 全格式保真”等超出验收范围的表述。

## 列表卡片外观设置

在“设置 → 外观 → 列表外观”中提供手动设置：

- 列表样式：紧凑列表、卡片列表。
- 显示卡片边界：独立开关，开启时绘制细边框。
- 显示轻阴影：独立开关，开启时绘制轻阴影。

默认保持现有紧凑布局。选择卡片列表后可调整边界与阴影；切回紧凑列表时禁用这两个附属选项，但保留已保存的偏好。设置页提供效果预览，应用设置后刷新列表，保存并在重启后恢复。卡片保留小间距，悬停、选中、置顶状态清晰可辨，深浅主题均适配。

复用虚拟列表，只绘制可见条目；同步修正滚动范围、命中测试、拖出和多选区域。字体与行高完成后再调整卡片，避免重复修改几何计算。该项不得使搜索结果呈现或列表滚动相对同构建基线明显变慢。

验收覆盖边界与阴影的四种开关组合、样式切换、预览与实际效果一致、保存重启及旧配置升级；任意组合下选中状态清晰，滚动、点击、多选和拖出位置正确。

## 开发顺序与发布门槛

设置导航按常规、外观、剪贴板、快捷键与 VV、分组、插件、多端同步、关于八个分区组织。常规聚焦启动和托盘；列表字号、卡片与窗口行为归入外观；记录、格式、粘贴和音效归入剪贴板；短语标题开关归入分组。各页独立保留滚动位置，未访问页面的保存操作不得重置原设置。

| 阶段 | 工作内容 | 阶段交付 |
| --- | --- | --- |
| 第一阶段 | QQ 完整复现与按键事件跟踪；搜索分段测量、取消和热点优化 | VV-01、SEARCH-01 的修复与自动回归；QQ 实机证据与搜索性能报告 |
| 第二阶段 | 修复粘贴音效与图片另存；字号设置、布局适配和 VV 全文预览 | SOUND-01、IMAGE-01 的行为回归；FONT-01、VV-02 完整交互与跨 DPI 验收 |
| 第三阶段 | 短语标题、富文本载荷、迁移、写回、去重和兼容矩阵；按余量纳入卡片 | PHRASE-01、CLIP-01 的数据闭环与格式样本；可选 UI-01 |
| 第四阶段 | 升级、配置、隐私、普通版与无局域网版回归 | 1.0.9 候选包、正式发布包和匹配的更新说明 |

单人串行预计约 16–25 个工作日，包括集成验收；第一阶段预计 5–8 人日。可并行进行搜索与 QQ 输入修复，但需要明确共享数据层和输入状态文件的修改边界。短语标题与富文本共用数据模型和迁移入口，应合并设计迁移，分别验收。工期以第一阶段实测和复现结果校准。

如 QQ 问题继续造成草稿丢失，VV-01 通过专项及必要回归后，可独立发出维护补丁；字号、富文本和卡片不阻塞该补丁。

正式版发布前必须满足：

- QQ 取消后继续输入、多行草稿、输入法切换与焦点切换全部通过，不能仅验证候选窗口关闭。
- 搜索达到约定数据规模的响应目标，查询取消、正确性与敏感内容隔离全部通过。
- P1 功能达到各自验收条件，兼容范围和未支持格式准确呈现。
- 旧设置和旧历史可迁移；正式数据迁移前备份，失败可恢复。新增格式载荷与索引不会破坏旧数据。
- Windows 普通版与无局域网版完成编译、现有回归及专项行为测试；涉及共享布局的改动执行受影响平台的编译检查。
- README 下载入口、软件版本号、更新元数据、发布说明与包校验信息一致。

自动测试覆盖状态转换、过期事件、查询取消、搜索语义、格式载荷和迁移等行为；源码字符串断言不替代 QQ 输入、真实粘贴、高 DPI 和搜索耗时验收。

每项缺陷保留受影响版本、复现场景、处理状态和验收结果，发布说明对应具体修复项。无法复现的条目继续保留定位任务与采集方案；维护补丁与功能版本分别记录进展，避免已确认的使用故障长期等待功能开发。
